Case study - No. 04

vkeys

PublicRust - DPAPI - XChaCha20-Poly1305

A machine-wide key store where named profiles inject credentials into a fixed command. An agent can use a key, but no command prints it.

The problem

Agent tooling spreads credentials: a dotenv here, an exported variable there, a key pasted into a prompt. Each copy is another place a value can leak, and a leaked provider key is spent before anyone notices. vkeys stores a key once and injects it into a named profile. The profile command is fixed, so there is no generic "run this and show me the environment" path.

Constraints

  • No command that prints, exports, or copies a stored value. There is no get.
  • Profiles carry a fixed argv and a fixed environment; callers cannot supply a command.
  • Profiles are human-only unless marked agent-ok, and refuse without a TTY.
  • Child processes get a clean environment and scrubbed output.
  • Every run appends to a local audit log.
  • Tier 2 keeps the provider key inside a separate broker process.

Evidence

v0.1.0 shipped on 2026-11-12 under Apache-2.0. The release reports 30 passing tests: 3 unit, 19 broker, 3 CLI, and 5 key-selection. On Windows, an elevated SYSTEM install was verified for install, boot start, health, ACL boundary, and a real broker completion; the agent could read only the use-only broker token. On Linux ARM64, a dedicated system user held the same boundary and the broker returned 200. Six platform archives ship with matching SHA-256 sidecars, and the vault key fingerprint makes a wrong master key fail before any write.

What I own

Architecture, the Rust CLI and broker, both vault backends, the master-key selection rules, the deployment recipes for Windows and Linux, the release pipeline, and the threat model. The claim I care about is the boundary: a credential can be used without a command that reveals it.

Limits

Tier 1 runs as the same user, so a process running as you can ask the OS to decrypt the vault. It makes accidental exposure hard, not impossible. The strong boundary is a separate OS user for the broker. macOS builds are unsigned, and 0.1 has no streaming, per-client budget, portable vault, or transport. The audit log is append-only, not tamper-proof.
