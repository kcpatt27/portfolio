Case study · No. 01

eyewright

Published · BetaPython · MCP · local models

A local-first decision core: a measured committee of local models behind one typed call, with the gate policy and decision trace attached.

The problem

Agent loops have to decide whether an artifact is done, which option is right, or whether to ask a human. A single small model is fast but weak; a strong cloud model sends the decision off the machine. eyewright packages that decision step as one typed call, with the policy and trace attached.

Constraints

  • The result must be a typed decision with an audit trail, not a free-form chat completion.
  • The default path stays local; a cloud eye is opt-in and its egress is labelled.
  • One package, four surfaces: Python, CLI, HTTP, and MCP.
  • The gate policy has to be measured on held-out decisions rather than asserted.

Decisions

  • Three-eye gate. A main local eye decides; consult eyes enter only in the uncertain band. Accept, reject, and consult are explicit outcomes rather than a confidence score with no consequence.
  • Agreement is not a vote. In the replay, naive majority voting underperformed the best single model. Agreement tiers became confidence labels, and the shipped design uses a consult cascade.
  • One package, four surfaces. Python, CLI, HTTP, and MCP share one config and one typed result.
  • Trace every decision. Policy and primary errors travel with the answer, so a degraded path never looks like a confident one.

Evidence

v0.4.0 shipped to PyPI. pypistats reports 143 downloads in the week ending 2026-10-19. The 2,000-decision replay covered five models and four committee designs; the selected policy reached 88.9% acted accuracy at 22.5% coverage. Coverage is the share of decisions acted on without escalation; the rest were reviewed or refused. The default gate is fully local.

Limits

The package is public on PyPI; the source repository is not public yet, so this record links to the package only. The benchmark is a screening result, not a production guarantee. Downloads are distribution, not production use. A configured cloud eye sends decision state off the machine; the package labels that trade rather than hiding it.
